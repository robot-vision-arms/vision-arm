## 2주차: ROS2 발행 ✅

- **실제 폰 영상으로 `vision_node` 실행:** `/vision/detections`, `/vision/debug_image` 발행을 확인했다.
- **영상 지연 수정:**
  - 원인: 폰은 초당 약 28장을 보내는데 노드는 10 Hz로만 읽어서, 버퍼에 오래된 프레임이 쌓였다.
  - 수정: 백그라운드 스레드가 계속 읽고 **최신 프레임 1장만** 보관한다.
- **WSL 시계 튐 해결:**
  - 원인: WSL의 NTP와 Windows 시계가 서로 번갈아 시계를 고쳐서 약 5초씩 앞뒤로 튀었다. 그때마다 ROS 타이머가 멈췄다.
  - 해결: `systemd-timesyncd`를 껐다.
  - 결과: 4.5 Hz → **10.0 Hz**, 최대 간격 115 ms.
- **끊김 자동 재접속:**
  - 폰 앱을 껐다 켜도 노드를 다시 시작하지 않고 수신이 재개된다.
  - 재연결 간격은 0.5초에서 시작해 실패마다 2배, 최대 5초로 늘린다.
  - FFmpeg 오류 로그가 40줄에서 7줄로 줄었다.
- **대체 물체 시험:** 초콜릿은 nut, 치약은 screw로 분류됐다.
- **mm·각도 발행 확인 (11-20):**
  - 동경 보정 파일로 처음 실행하자 해상도가 달라 패킷이 0개였다. 폰이 세로로 보내고, 폰·시트 위치도 보정 때와 달라져 있었다.
  - 회전 270으로 맞추고 작업 시트 사진으로 homography를 다시 만들었다. intrinsics는 동경 파일 그대로 쓴다 (왜곡 계수 0이라 homography에 영향 없음).
  - 빈 시트: 10.1 Hz, `calib_ok: true`, 마커·시트 밖 물체 **오검출 0개**.
  - 나사·너트를 올리자 나사 (139.8, 102.2) mm 23.9°, 너트 (212.2, 68.1) mm로 **null 없이 발행**됐다. 흔들림은 x 0.13 mm, 각도 0.29°.
- **남은 일:** (선택) 폰으로 재접속 동작을 다시 확인한다.

## 3주차: 스폰·흡착 ✅

- **`object_spawner.py`:**
  - 비전 패킷의 부품을 Gazebo `obj_0`~`obj_2`로 스폰한다.
  - 미보정 패킷과 unknown 부품은 거부한다.
  - 서비스: `/sim/spawn_objects`, `/sim/clear_objects`.
- **DetachableJoint 동작 확인:** 지웠다 다시 만든 같은 이름 모델도 attach하면 새 모델을 잡는다.
- **TF·RViz:** 스폰한 부품을 TF(`base_link→obj_k`)와 RViz 마커로 발행한다.
- **진공 흡착 판정 `/sim/vacuum`:** 간격, 밀봉, 흡착력과 무게를 현실 조건으로 검사한 뒤 붙인다.
- **컵 두 개 헤드 (URDF 수정은 사용자 승인):**
  - **5 mm 컵 (나사용):** 흡착력 1.18 N. 나사 무게는 0.20 N이다.
  - **센터링 핀 링 컵 (너트용):**
    - 위치는 tool0 +X 12 mm다.
    - 입술 안 지름 9 mm, 바깥 지름 12 mm, 핀 지름 7.6 mm다.
    - 위치가 ±1.5 mm까지 어긋나도 핀이 너트를 가운데로 맞춘다.
    - 흡착력은 2.97 N이다.
  - 2 mm 마이크로 컵도 시도했지만 위치 여유가 ±0.25 mm뿐이라 버렸다.
- **확인 스크립트 `scripts/check_spawn_week3.py`:**
  - Gazebo·RViz 창을 띄우고 5회 반복해서 **5/5 통과**했다.
  - 너트 5/5, 나사 10/10 흡착. 놓인 위치 오차는 최대 1.5 mm다.
- **팀 코드 연동 (git pull 후):** 팀원 1·2의 확인 스크립트가 모두 통과했다.
  - `check_workcell_layout.py`
  - `team2_link.launch.py`, `check_team2_spawn_link.py`
  - `check_sim_week2.py`
  - `check_team2_repeat_motion.py`
- **실제 폰 → 스폰 노드 연결 (11-17):** TCP 전송과 ACK는 정상이었다 (지연 약 5.5 ms). 그때는 미보정 패킷이라 스폰이 거부됐다 (정상 동작).
- **실제 보정 패킷으로 스폰 확인 (11-20):**
  - 폰 → `vision_node` → TCP → `/robot/targets` → `/sim/spawn_objects` 로 나사·너트 2개 스폰 성공.
  - Gazebo 실제 위치(`gz model -p`)와 패킷 mm 차이 **0.01 mm 미만**, 각도 차이 0.0°.
- **테스트:** 전체 **137개 통과** (11-17).
- **남은 일:** 너트는 링 컵 기준으로 툴을 −X 12 mm 옮기는 것을 `pick_place_node.py` 담당과 협의한다. `/sim/run_cycle` 자체는 동경이 11-20에 구현했다.

## 4주차: 실측 정답·시연 준비 🟡

- **수집 도구 `scripts/collect_ground_truth.py` (11-20):**
  - 자세 30개(나사 24 = 0~165° 15° 간격 ×2, 너트 6)를 하나씩 화면에 띄우고, 부품을 놓은 뒤 s로 사진과 정답(`poses.csv`)을 저장한다.
  - 수집 중에는 예측값을 보여 주지 않는다. 보면서 놓으면 정답이 예측 쪽으로 오염되기 때문이다.
  - 시트 마커가 보정 위치에서 3 px 넘게 벗어나면 `SHEET MOVED`를 띄우고 저장을 막는다.
  - `--only`로 일부만 다시 찍고, `--print-sheet`로 자세를 그린 A4 인쇄 시트 PDF를 만든다.
- **임시 정답 30개 (11-20, 화면 안내선 방식):**
  - 프린터가 없어 화면 안내선에 맞춰 놓았다. 이 방식은 정답이 보정에 의존해서 임시용이다.
  - 수집 직전 시트가 약 45 mm 밀려, 수집 사진으로 homography를 다시 만들어 정답을 옮겼다. 4개(gt002·gt013·gt018·gt029)는 시트를 고정한 뒤 다시 찍었다.
  - 결과: 분류 **30/30**, 위치 MAE **1.85 mm** (기준 ≤ 2 mm), 각도 MAE **6.34°** (기준 ≤ 3°).
  - 각도 오차는 치우침 없이 ±7° 흩어져서, 검출 문제보다 화면 선에 손으로 맞춘 오차로 본다. 이 값으로는 KPI 달성 여부를 판단하지 않는다.
- **다음 주:**
  - `data/ground_truth/pose_sheet.pdf`를 100% 배율로 인쇄하고 100 mm 선을 자로 확인한다.
  - 시트를 **테이프로 고정**하고 homography를 다시 만든 뒤 `--method print`로 30장을 다시 찍는다 (최종 정답).
  - 시연 준비. 촬영과 시연 중에는 폰 자동 잠금을 끈다. 앱이 백그라운드로 가면 송출이 멈춘다.

## 팀과 정할 것

- `params.yaml`의 `camera_rotate_deg`를 270으로 바꿀지 (폰이 세로로 보내는 동안).
- 정답 평가 때 동경의 높이 시차 보정(`px_to_mm(height_mm=...)`)에 나사·너트 높이를 몇 mm로 넣을지.
- 은색 나사가 조명에 따라 `min_area_px`(500)보다 작게 잡혀 미검출된 장면이 있었다. 검출 담당과 공유.
