작성 2026-11-27 동경 · 상태: **계획** (아직 만든 것 없음)

- **3주차 (보충)**: 지금 3주에서 못 끝낸 것을 **고친다** (각도 3° 이하, 팔 동선, 조명·새 부품, 실물 모드 성공률).

## 2. 3주차 (보충): 남은 개선 과제

### 0-A. 각도 3° 이하로 줄이기 (동경)

**지금**: 공식 KPI(11-25 인쇄 선 정답 30장)에서 각도 오차 규칙 4.41°, YOLO 3.15°로 목표(≤ 3°) 미달.
크게 틀린 두 장(gt003, gt013)은 **손으로 놓을 때 비뚤어짐 4~8°** 와 YOLO 오차 2~6° 가 겹친 것이다 ([PORTFOLIO 8.4](PORTFOLIO.md)).
즉 오차의 일부는 모델이 아니라 **정답 쪽**에 있다.

| 순서 | 할 일 | 끝났다는 기준 |
|---|---|---|
| 1 | **정답부터 바로잡기**: 30장 모두 사진에서 놓기 비뚤어짐을 잰다 (지금은 2장만 잼). 지그(나사를 끼워 각도를 고정하는 틀)를 3D 출력하거나 자로 대고 다시 찍는다 (가영) | 놓기 오차 표 30장, 다시 찍은 정답 30장 |
| 2 | **각도 다듬기**: YOLO 상자 안에서 부품 픽셀만 골라 장축을 다시 계산 (윤곽선 `minAreaRect` 또는 PCA). 상자는 YOLO, 각도는 픽셀로 | 같은 test 에서 다듬기 켬·끔 비교 |
| 3 | **여러 장 평균**: 멈춘 부품이므로 5~10 프레임의 각도를 평균(또는 중앙값) | 프레임 수별 각도 오차 |
| 4 | 그래도 넘으면: 입력 크기(imgsz) 키우기, 각도 라벨 다시 확인 | 위치·속도(10 Hz) 유지 확인 |

- **목표**: 새 정답 30장에서 YOLO 각도 오차 **3° 이하**, 위치 2 mm 이하 유지, 10 Hz 유지.
- **주의**: 정답을 바꾸면 11-25 값과 직접 비교할 수 없다. 옛 정답·새 정답 두 값을 같이 적는다. 설정은 val 사진으로만 정하고 test 는 한 번만 쓴다.

### 0-B. 팔이 돌지 않는 최적 동선 (성민)

**지금**: 한 개 집는 데 약 15초. 부품마다 **대기 자세로 돌아갔다가** 다시 가고, 큰 이동에서 관절(특히 손목)이 멀리 도는 해가 나올 수 있다.
`nearby_ik` (가장 가까운 역기구학 해)와 `compact_cycle_return` (대기 자세 생략, 기본 꺼짐)은 이미 있다.

| 순서 | 할 일 | 끝났다는 기준 |
|---|---|---|
| 1 | **지금 상태 재기**: 한 개당 시간을 구간별(이동·하강·흡착·상자·복귀)로, 관절마다 움직인 각도 합 기록 | 구간별 시간 표, "많이 도는" 경우 목록 |
| 2 | **관절 범위 줄이기**: 손목 관절(특히 wrist_3) 허용 범위를 ±180° 안으로 제한해 한 바퀴 도는 해를 막는다. 컵이 둥글어 툴 yaw 는 0 고정이므로 손목을 돌릴 필요가 없다 | 관절 각도 합이 줄었는지, 계획 실패가 늘지 않았는지 |
| 3 | **대기 자세 생략**: 부품 사이에 대기 자세로 돌아가지 않고 상자 위 → 다음 부품 위로 바로 (`compact_cycle_return` 켜고 시험) | 9개 3회 성공률 유지 + 시간 |
| 4 | **집는 순서**: 가까운 부품부터 (지금 팔 위치·상자 위치 기준 최근접) | 한 사이클 총 이동 거리 |
| 5 | **경유점 고정**: 작업 매트 ↔ 상자 사이에 관절 각도 경유점을 정해 매번 같은 길로. 필요하면 직선·관절 보간 플래너(Pilz) 시험 | 매번 같은 경로인지 (궤적 비교) |
| 6 | 속도·가속도 비율 올리기 (0.5 → 0.6~0.8), 궤적 추종 오차 확인 | 성공률 유지하면서 시간 |

- **목표**: 한 개 약 15초 → **8초 이하**(분당 약 4개 → 8개), 손목이 한 바퀴 도는 일 0회, 반복 시험 성공률 유지 (27/27 수준).

### 0-C. 다른 조명·새 부품, 실물 모드 성공률 (가영 · 동경)

| 할 일 | 끝났다는 기준 |
|---|---|
| 다른 조명(형광등만·창문 빛·어두움) 3가지, 처음 보는 나사·너트, 빈 시트, 기타 물체 사진 촬영 (가영) | 조건별 10장 이상 |
| 라벨 후 규칙·YOLO 를 같은 기준으로 재기 (동경) | 조건별 F1 표. 떨어진·붙은 부품을 나눠서 |
| 붙은 부품의 **위치·각도 오차**도 따로 재기 (지금은 찾은 개수만 나눔) | 떨어진 vs 붙은 부품 오차 표 |
| 실물 모드 Pick: 검출 좌표로 놓인 부품을 집는 방식으로 성공률 재기 (`respawn` 은 근거로 안 씀) | 실물 사진 기준 성공률 |

## 3. 4~6주차: 고도화

전체 흐름:

```txt
컨베이어 ─ 카메라 ─┬─ 추적·예측 (1번) ───── 번호, 위치, 속도 ─┐
                  └─ 양품/불량 판정 (5번) ─ 번호, 판정 ──────┴→ 로봇 → 나사 / 너트 / 불량 상자
```

- 1번은 "어디에 있고 어디로 가나", 5번은 "양품인가 불량인가" 라서 따로 만들 수 있다. 번호(`track_id`)로 합친다.
- 2번은 5번에 부족한 불량 사진을 만드는 데 쓴다.

### 첫날(4주차 월) 셋이 정할 것

| 정할 것 | 제안 |
|---|---|
| 부품을 묶는 값 | `track_id` |
| 추적이 보내는 것 | 번호, 위치 (mm), 속도 (mm/s), 촬영 시각 |
| 검사가 보내는 것 | `quality: ok / ng / unknown`, 점수 |
| 검사가 늦거나 실패 | `unknown` 으로 두고 **추적과 집기는 계속** |
| 상자 | 나사, 너트, 불량 3개 |
| 카메라 | 추적용 1대 + 가까운 검사용 1대 (지금 카메라는 너트가 약 34 px 라 흠집 검사가 안 됨) |

### 주차별

| 주 | 1번 성민 · 가영 | 2·4·5번 동경 | 끝났다는 기준 |
|---|---|---|---|
| 4주차 | Gazebo 컨베이어 (초당 20·50·100 mm), 부품 추적과 번호 유지 | 4번 최소판: Docker, push 하면 테스트 자동 실행 (2~3일) → 5번 시작: 공개 데이터(MVTec AD screw·metal_nut)로 이상 검출 기준선 | 번호가 유지됨 · 자동 테스트 통과 · 공개 데이터 점수 |
| 5주차 | 속도 추정, 집는 순간의 위치 예측, 예측한 자리에서 기다렸다 집기 | 우리 부품 양품·불량 촬영과 평가, Gazebo 로 모양 불량(짧은 나사, 막힌 너트) 사진 자동 생성 | 예측 위치 오차 측정 · 실물 test 결과 |
| 6주차 | 벨트 속도별 성공률, 예측 켬·끔 비교 | 합성 사진을 넣기 전·후 실물 점수 비교 → 1번과 번호로 합치기 | 성공률 그래프 · 비교표 · 통합 시연 |

**왜 예측이 필요한가**: 초당 50 mm 벨트에서 지연 85.5 ms (11-25 실물 폰, YOLO, P95)면 부품이 약 4.3 mm 움직인다. 너트 링 컵 허용 ±1.5 mm 를 넘으므로 **집는 순간의 위치**를 계산해야 한다.

**집는 방식 단계** (막히면 앞 단계로): ① 정해진 자리에서 벨트 멈추고 집기 → ② 예측한 자리에서 기다렸다 집기 (**목표**) → ③ 벨트와 나란히 움직이며 집기.

## 5. 위험과 대비

| 위험 | 대비 |
|---|---|
| 정답을 다시 찍어도 각도 3° 를 못 넘음 | 각도 다듬기·여러 장 평균을 먼저 val 에서 확인. 안 되면 원인(모델 / 정답 / 보정)을 나눈 표를 결과로 남김 |
| 관절 범위를 줄이면 계획 실패가 늘어남 | 범위를 단계적으로 줄이고, 경유점(관절 각도)으로 큰 이동을 고정 |
| 로봇이 느려 컨베이어를 못 따라감 | 0-B 를 3주차에 먼저. 그래도 느리면 집는 방식 ① 로 |
| Gazebo 와 YOLO 를 같이 켜면 5.1~5.4 Hz | 떨어진 부품은 규칙(같이 켜도 약 10 Hz), GPU 또는 PC 두 대 분리 |
| Gazebo 에는 진짜 흠집이 없음 | Gazebo 는 모양 불량, 흠집·녹은 실물 사진 |
| 불량 사진 부족 | MVTec AD 로 시작 (비상업 이용 조건 확인) |
| 공개 데이터 점수가 우리 부품에서 안 나옴 | 우리 사진으로 꼭 확인 (YOLO 때 F1 0.989 → 0.504 경험) |
| 동경 혼자 0-A + 세 주제 | 4번을 작게, 2번을 5번 데이터로 묶기 |

## 6. 시간이 모자라면 줄이는 순서

1. GPU 가속, Docker 세부
2. 합성 사진 종류 수

**끝까지 남길 것**: 각도 3° 결과(못 넘어도 원인 표), 팔 동선 전·후 시간 비교, 예측 켬·끔 비교, 벨트 속도별 성공률 그래프, 실물 test 평가.
